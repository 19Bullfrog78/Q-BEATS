C4) TRAPPOLE D'AMBIENTE DI QUESTA MACCHINA — il referee NON le puo' misurare
================================================================================
Tutte [V] su questa macchina (Windows 11, MSYS2/Cygwin bash del tool CC).
Le cinque forme di falso-negativo sono ora INCISE in LIBRO v42, Sez.2, riga
REGOLA INDIRIZZO DI CONTENUTO. Qui il dettaglio d'ambiente che la riga compatta:

T-C4.1  core.ignorecase = true. git show <sha40>:<path> con UNA lettera di
        case sbagliata nel path rende:
          «fatal: path '…' exists on disk, but not in '<sha>'»
        MENTRE il file ESISTE a quel commit (cat-file -e exit 0) e il
        filesystem apre lo stesso path minuscolo senza protestare.
        Il messaggio per il path DAVVERO assente e' DIVERSO:
          «fatal: path '…' does not exist in '<sha>'»
        GUARDIE: git cat-file -e <sha40>:<path> · git ls-tree --name-only.

T-C4.2  Pattern multi-parola su file a capo fisso: grep -c rende 0 sul file
        che CONTIENE la frase. E il rimedio ovvio, tr '\n' ' ', rende ANCORA 0
        se la continuazione e' indentata (a capo -> 'NESSUN' + 7 spazi +
        'commit'). Cura vera: tr -s '[:space:]' ' ' (spazi COLLASSATI).
        Controllo positivo che isola la causa: su frase tutta-su-una-riga il
        join semplice funziona -> non e' il filtro, e' l'indentazione.

T-C4.3  bash ${#var} conta BYTE (locale di questo ambiente); python len()
        conta CODEPOINT. Stessa cella: 2421 byte = 2364 codepoint. Un valore
        atteso senza il nome dell'unita' fa abortire un confronto giusto
        (successo ad abort-1 di MISURE_R3). Dichiarare SEMPRE l'unita'.

T-C4.4  gh run list --commit con sha CORTO rende [] exit 0 (falso-zero,
        gia' agli atti). E il workflow CI parte per EVENTO DI PUSH sul tip:
        in un push di due commit il commit intermedio NON ha run — un []
        legittimo, da non leggere come guasto. Oggi: push in DUE passi
        apposta, una run per commit, entrambe verdi (MISURE_R5).

T-C4.5  Python su questi file: aprire in 'rb', MAI text-mode (newline
        translation); i file a due facce si editano sui byte con ancore
        verificate e abort PRIMA della scrittura. Regge: tre abort reali
        oggi, zero file toccati nei tre casi.
