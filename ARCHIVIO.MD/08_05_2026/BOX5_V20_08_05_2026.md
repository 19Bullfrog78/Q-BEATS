### Grid verticale fissa

```
8%  header
10% slot metronomo

4%  micro bar
35% giant text (teleprompter)

```

Total: 100%.

### Header

```
[ ← BACK ]  [ LED·LED·LED  {song.name}  ·  {bpm}[🔒]  ·  {time sig} ]  [ SVG MUTE ]
```

- `song.name` — JetBrains Mono 700, 28px
- BPM — JetBrains Mono 400, 17px. Lucchetto SVG se `backtrackFilename != nil` (opacity 0.45)
- Time sig — JetBrains Mono 400, 15px
- Mute button top-right: SVG speaker. Attivo = onde sonore bianco 85%. Muto = barra diagonale ambra `#f5b820`
- 3 LED 5px, invisibili se non attivi
- Stato STOPPED: aggiunge separatore `·` + label "STOP" JBMono 600, 10px caps, opacity 0.35

### Slot metronomo

N slot = beatsPerBar. Flash singolo frame ~16ms, no decay, no easing.
- Accento: `#d43f00`
- Beat: `rgba(255,255,255,0.85)`
- Subdivisione: `rgba(255,255,255,0.20)`
- Off: `rgba(255,255,255,0.08)`

SubdivisionMultiplier = audio-only, zero impatto visivo.

### Bar counter

"Battuta X di Y". Display "— / —" se total ≤ 0.
- Count-in / Standby → "— / —"
- Loop ∞ → "Battuta X di ∞"

### Micro bar

Segmentata N segmenti = N battute della sezione corrente.

### Giant text (teleprompter)

`Section.name`. Se vuoto → BPM sezione come fallback. Mai coesistenti.

### Macro bar (2%)

Segmentata N segmenti = N sezioni canzone.

### Zona NEXT (10%)

Label statica `NEXT:` (JBMono semibold, 10pt, tracking 2, `rgba(255,255,255,0.25)`)
seguita da nome dinamico (Inter ExtraBold, 34pt, `rgba(255,255,255,0.45)`).

- Sezione successiva stessa canzone → `NEXT: {nextSection.name}`
- Ultima sezione + canzone successiva → `FINE · NEXT SONG: {nextSong.name}`
- Ultima sezione ultima canzone → zona vuota

### Handle strip (2%)

- Posizione: tra zona NEXT e Transport
- Contenuto: barretta 32×3pt, `rgba(255,255,255,0.20)`, corner radius 1.5
- Funzione: affordance visiva per gesture mixer

### Transport

Tasti: Play/Stop · Loop · KILL BASE · EMERG. Dettagli identici a V19.

- Tap sul pannello mixer → chiude
- Tap su `Color.clear` 49% sopra il pannello → chiude

## Limite v1 — Modalità Direttore

**Comportamento atteso (NON è bug):**

In modalità Direttore + Q-B in play, durante il movimento attivo del BPM da parte di un peer (es. ruotare la manopola SB), può verificarsi desync transitorio di fase del peer fino al rilascio della manopola e a qualche secondo di stabilizzazione.

**Causa fisica:** Link è protocollo peer-to-peer. Quando un peer modifica il session tempo, c'è una finestra di latenza WiFi (~10-50ms) prima che il re-broadcast di Q-B raggiunga il peer. In quella finestra il peer suona effettivamente al BPM che ha scritto, accumulando drift di fase. Il tempo converge al rilascio (Q-B vince), la fase resta drappata.

**Non riproducibile in uso live normale:** toccare il BPM di un peer durante un brano è errore d'uso, non flusso normale. Per allineamento iniziale, il flusso corretto è: Q-B fermo → impostare BPM → premere Play.

**Soluzione architetturale (rimandata a v2):** phase assertion attiva via `ABLLinkRequestBeatAtTime`. Richiede modifica Layer 2 con rischio regressione tipo Build #307. Da rivalutare se segnalata in performance reali.
